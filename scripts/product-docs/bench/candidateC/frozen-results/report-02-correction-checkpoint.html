05 · Multi-Record Relevance Fix

A record can now declare its own relevance

The schema gained two optional fields: recordRole ('primary' by default — unchanged behavior for every record written before this checkpoint) and, for a 'scoped' record, scopedQuestionTypes — the question-classifier types it's eligible to contribute to. filterRecordsByRelevance() applies this before dimension selection: a scoped record participates only if the current question's type is in its declared list, or the recovery gate fired and it has real recovery content to offer.

QMZ's troubleshooting record is now tagged scoped with ['TROUBLESHOOTING', 'CONNECTIVITY']. The mechanism itself is entirely general — declared once in schema.js and conceptualRetrieve.js, with zero QMZ-specific code anywhere in the retrieval layer. Any future feature that grows a second, narrower companion record gets the identical protection by declaring the same two fields.

What is Duplicate Detection?
Assistant
Duplicate Detection prevents the same file from being imported twice, ensuring that no destination file is overwritten. For Quick Import, it also warns you beforehand if files you are about to import already exist at the destination. It operates with two layers: 1. **Layer 1 (Automatic):** This is built into the copy engine and performs a mechanical name-and-size comparison against the destination folder for every file, without operator visibility. 2. **Layer 2 (Pre-check, Quick Import only):** Before copying begins, AutoIngest compares each selected file's name and size against a snapshot of the destination folder. If there is a match, an interactive warning is displayed. This second layer is only available during Quick Import; the full grouped Event Import relies only on Layer 1.

Why is QMZ separate from normal Event Import?
Assistant
QMZ is a separate, standalone workspace used by archivists to classify already-ingested QMZ (Qadam/Majlis/Ziyafat) material into numbered real-world-occurrence sequences (like 01Q or 02M). This replaces the previous process of manually creating folders and sorting files in Finder or Adobe Bridge. QMZ operates independently from normal Event Import in a few ways: * **Date Reading:** It reads the original embedded capture date from the media file's metadata, not the file's copy date on disk (which is used only as a fallback). * **Workspace State:** It maintains its own independent state (such as grid sort order, view mode, etc.), meaning settings from the standard Import workspace do not carry over when switching to QMZ.
